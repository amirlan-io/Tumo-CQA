## Обоснование кандидата

На основании [проверенных гипотез](hypotheses-results.md), без обещания заранее известного прироста:

- **H1:** явно распространять «не оцениваются» на весь перечисленный набор; соблюдать область исключения, не вводить свой SLA.
- **H2:** проверять отрицательные утверждения по всему релевантному диапазону и учитывать контрпримеры. Дословная цитата — средство проверки, не доказательство вывода; обязательный косметический префикс не вводится.
- **H3:** оставить один запрос для всех критериев; разбиение не доказало выгоду.
- **H4:** уточнить выбор по наиболее конкретному подходящему описанию шкалы и отдельно измерить повторяемость. Промпт не гарантирует детерминизм.
- **H5:** явно соблюдать приоритет N/A при достаточном исходном контексте и не переносить дефект между независимыми критериями.
- **H6:** честно отделять полноту от независимо проверенной правильности. Настоящего справочника нет; RAG и фиктивные корпоративные правила не добавляются.

В v3 не включены ID диалогов, готовые ответы, фиксированные c1…c8 или значения корпоративных шкал. Все настройки поступают из версии API. Рабочий default v1 не переключается.

Один RU-звонок обязателен; N/A и gross=yes найдены без замены выбранных кейсов.

Это holdout относительно разработки v3, не неизвестный модели официальный PROD и не dataset, никогда не проходивший через v1: ранее v1 уже оценивала полный DEV65. Ни один эталон не утверждён человеком или организаторами.

## Порядок и лимит

1. На обновлённом коде заново сравнить **v1/v2/v3** на всех 18 выбранных диалогах: **54 начальных запроса**. В каждом диалоге одинаковы модель, критерии, конфигурация и схема; меняется только выбранная версия промпта. Порядок прямой/обратный чередуется, v2 остаётся средней в трёхсторонней паре — ограничение дизайна.
2. Повторяемость: `p1-ru-001`, `p1-kz-008`, `p1-en-015`, по три одинаковых full-checklist запроса **v2 и v3**: **18 начальных запросов**. Используется существующий изолированный research client; schema name в этом опыте постоянный `dialogue_research`, поэтому его результаты не смешиваются с обычными оценками в главной таблице. Проверяются hashes исходных запросов, provider/model и repair.
3. Всего **72 начальных запроса** плюс максимум один repair контракта на задачу. Последовательно, пауза 4 секунды вне измеряемой задержки; транспортных retries нет. Сбои сохраняются как сбои, оценки не выдумываются. Повторного выбора удачнейшей попытки нет.
4. Независимый source-аудит объяснений v2/v3 по всем 18 диалогам, без подмены его совпадением с draft. Выделяются definite unsupported facts, непроверенные правила и ASR-сомнения; ссылки с другим достаточным набором не считаются ошибкой сами по себе.

До вызовов фиксируются hash промптов, реализации, выбранной API-версии, обоих gold и исходного dataset в приватном `data/ai-results/v3-plan.json`. При изменении исходников опыт останавливается. Старое исследование гипотез не возобновляется с новым кодом: его fingerprints намеренно устарели после pull.

## Метрики и решение

- Основная: точное совпадение `answer + raw_score` на **72 новых решениях**, отдельно по языкам и по 63 заранее не отмеченным как спорные.
- Регрессия: 72 известных решения, отдельно; не объединять автоматически с новым набором в показатель обобщения.
- Все ошибки контракта и обработки, диапазоны/нумерация, фактические ошибки объяснений, latency, reported usage/cost.
- Повторяемость: число меняющихся позиций «диалог × критерий» из 24 на версию; отличие формулировки отдельно. Основной hash-тест — результаты без repair при одинаковом provider/model.

Положительный сигнал для кандидата: больше совпадений на новом наборе, без падения общей регрессии, увеличения source-based фактических ошибок или пропуска грубых нарушений; валидные результаты и не ухудшившаяся повторяемость также проверяются. Равенство/ухудшение не объявляется улучшением. Малый объём не даёт статистической гарантии; default не меняется автоматически даже при положительном результате. Метки не исправляются под ответы. Следующая правка промпта потребует новой версии и отдельного плана.
