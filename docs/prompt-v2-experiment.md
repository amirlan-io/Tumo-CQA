# Эксперимент с промптом v2

Дата: 2026-11-07. Модель: `stealth/crouton-alpha`, тот же OpenRouter endpoint, JSON Schema и версия исходного чек-листа. **Итог: v2 улучшает совпадение с предварительной разметкой и соблюдение формата, но не прошла допуск на замену v1 из-за фактических регрессий.** По умолчанию остаётся `v1`; официальный DEV-файл не пересчитан.

## Что изменено

Новый [`evaluate-v2.txt`](../server/prompts/evaluate-v2.txt) усиливает:

- проверку N/A до выбора положительного/отрицательного ответа;
- разбор обязательных частей составного критерия, а не зачёт одного прощания;
- выбор шкалы по описанию и конкретному оставшемуся вопросу;
- независимость полноты консультации, ясности, эмпатии и грубого нарушения;
- различие обещания и выполненного действия, сожаления и извинения;
- ограничения выводов по ASR, скрытым именам и непроверенным правилам;
- самопроверку восьми объектов и обязательных диапазонов.

Текст v1 сохранён **байт-в-байт**. Ни v1, ни v2 не содержат готовых оценок, ID диалогов или встроенных c1…c8. Условия и шкалы по-прежнему берутся из выбранной конфигурации. Публичный контракт `evaluateDialogue`, score, маршруты и БД не менялись.

В `createEvaluator({promptVersion: 'v2'})` появилась явная версия. Она согласованно задаёт текст system prompt, имя схемы, `output.prompt_version` и диагностику. Неизвестные/похожие на пути версии отклоняются до fetch. Экспорт `prompt_version` для сервера выбирается через `AI_PROMPT_VERSION`; без него — v1. Это сохраняет согласованность с ключом кэша jobs. Исправлен CLI-loader, ранее допускавший только литерал v1.

## Дизайн до запуска

1. **Development:** прежние 9 диалогов / 72 предварительные оценки. Именно на их ошибках разрабатывалась v2. Этот набор не является независимым тестом.
2. **Holdout:** ещё 9 диалогов, по 3 RU/KZ/EN, в том числе звонок. Состав выбран главным агентом заранее; другой агент полностью прочитал транскрипты и зафиксировал [разметку](../tests/fixtures/ai-holdout.draft.json) и [неопределённости](ai-holdout-review.md), не читая ответы моделей или v2.
3. Автор v2 не читал holdout-транскрипты/разметку или выход полного DEV65. Holdout — относительно разработки промпта, **не набор, никогда не проходивший через v1**: предыдущий полный прогон уже включал все DEV.
4. Обе версии заново вызываются на одном и том же диалоге с одинаковой моделью, гиперпараметрами, полным snapshot версии и структурой ответа. Порядок v1/v2 чередуется. Gold и флаги неопределённости **не отправляются модели**.
5. Hash разметки, входа и исходников фиксируется в отчёте. При изменении промпта/реализации эксперимент останавливается. Метрика — точное совпадение `answer + raw_score`; семантика объяснений проверяется отдельно.
6. Обе разметки остаются `draft`, `approved_by=null`. **Ниже не официальная accuracy и не согласование с людьми.**

Holdout: `p1-ru-009`, `p1-ru-017`, `p4-ru-002`, `p1-kz-005`, `p1-kz-008`, `p1-kz-015`, `p1-en-004`, `p1-en-008`, `p1-en-013`. Он не пересекается с development. 20 спорных пар «диалог × критерий» объявлены **до** генерации. Совпадения по остальным 52 ответам приведены отдельно, без постфактум-исключений; отсутствие флага тоже не делает разметку экспертной.

## Реальные результаты после одного восстановления неполных пар

| Набор / показатель | v1 | v2 |
| --- | --- | --- |
| Development, 9 диалогов | **58/72 (80,6%)** | **63/72 (87,5%)** |
| Holdout, 9 диалогов | **56/72 (77,8%)** | **61/72 (84,7%)** |
| Holdout без заранее отмеченных 20 спорных оценок | **44/52 (84,6%)** | **49/52 (94,2%)** |
| Все 18 диалогов | **114/144 (79,2%)** | **124/144 (86,1%)** |
| Среднее время выбранных сопоставленных оценок, включая repair | **18954 мс** | **17292 мс** |
| Repair в выбранных полных парах | 7 | 0 |
| Ошибки контракта во ВСЕХ фактических попытках, включая заменённые пары | **7** | **1** |

Примеры улучшений относительно draft: `p1-ru-001/c2` и `p1-kz-005/c2` — yes → N/A; `p1-ru-001/c7`, `p1-en-001/c7`, `p1-ru-017/c7`, `p1-en-004/c7` — одно прощание больше не засчитывается как полный составной критерий. Есть и расхождения в обратную сторону, включая эмпатию и интерпретацию ASR. Сами по себе совпадения не доказывают правильность спорных меток.

### Сбои провайдера и правила восстановления

В исходных параллельных запусках было **3 HTTP 429** и **1 timeout**. Это сохранено в исходных отчётах; такие сбои нельзя представлять как ошибки понимания языка. После паузы 65 секунд один раз заново вызваны **обе версии** для трёх неполных пар: `p1-en-015`, `p1-en-008`, `p1-en-013`.

В таблице целиком использованы новые пары для этих трёх диалогов, даже когда ранее успешная оценка имела больше совпадений. Это **не best-of** и не замена только худшего результата. Остальные 15 пар не пересчитывались. Дополнительные вызовы разнесены паузами. Первичные сбои, ответы и hashes не удалены.

Всего **50 фактических попыток** с учётом repair и recovery; в 46 ответах есть `usage.cost`, их сумма **$0**. Для четырёх сетевых/HTTP-сбоев usage не получен: сумма доступных usage — не независимая сверка биллинга. Эксперимент мал, единичен и зависит от нагрузки preview-провайдера; разность времени не является SLA или статистической гарантией.

## Аудит фактических утверждений

Два агента отдельно сверили объяснения обеих версий с полными исходными транскриптами: 18 диалогов, 359 реплик, 144 criterion results на версию. Они не считали отличающийся набор номеров доказательств ошибкой и не подменяли проверку фактов совпадением с gold. Это **агентский аудит, не human approval**.

| Уникальных результатов с находкой | v1 | v2 |
| --- | --- | --- |
| Неподтверждённое фактическое утверждение | **4** | **4** |
| Безусловная оценка внутреннего правила без проверяемой базы | **2** | **3** |

В этих данных две категории не пересекаются; ASR-сомнения учтены отдельно, не включены в definite counts. Непроверенное правило не означает, что правило ложно. Реально подтверждённый клиентом успех навигации не приравнивался к выдуманному корпоративному регламенту.

**Блокирующая регрессия v2:** в `p1-en-013/c6` модель применила исключённый из исходной оценки трёхминутный SLA и написала, что после передачи прошло больше трёх минут. В исходнике от передачи до ответа — **2:13**. Кроме того, отказ от частной консультации назван переспрашиванием. Версия v2 также не устранила все неподтверждённые объяснения хронологии/необходимых деталей.

Следовательно, большее совпадение с draft ещё недостаточно для автоматической замены рабочего промпта. **V2 оставлена экспериментальным кандидатом.** Следующая итерация должна отдельно закрепить исключённые условия и проверяемость фактического объяснения, а не только добиваться совпадения числа баллов. Новую итерацию нельзя считать независимо проверенной на уже разобранном holdout без нового заранее отложенного набора.

## Воспроизведение и файлы

Из корня `Tumo-CQA`, с ключом только в `.env`:

```sh
npm run ai:compare-prompts -- \
  --dataset "/home/angel/Загрузки/Telegram Desktop/invoke.json" \
  --version-file data/ai-results/dev-checklist-version.json \
  --suite all \
  --allow-draft
```

Это новый реальный прогон, а не чтение сохранённых оценок. Без `--allow-draft` неподтверждённая разметка отклоняется. Можно выбрать `--suite development` или `--suite holdout`. Отчёты сохраняются после каждого ответа в приватном `data/ai-results/`; существующий файл или официальный `results/dev/results.json`/`results/prod/results.json` нельзя указать как `--output`. Это защищает итог сдачи от случайного отчёта эксперимента.

Для программного эксперимента используйте `createEvaluator({promptVersion: 'v2'})`. Для осознанного запуска всего сервера на кандидате можно задать `AI_PROMPT_VERSION=v2` и перезапустить процесс, но **это не рекомендация активации текущего кандидата**. `.env` в этой задаче не менялся. Один и тот же текст нельзя менять под прежней версией после принятия: новая правка требует новой версии и проверки.

При изменении реализации/промпта старый журнал полного DEV может намеренно отказаться от resume по fingerprint. Не редактируйте hash вручную; используйте отдельные journal/output для нового опыта. Готовый официальный DEV v1 сохранён, его повторный экспорт для этой задачи не нужен.

Приватные артефакты, не добавляемые в Git:

- `data/ai-results/prompt-comparison-development-1794063740424.json`;
- `data/ai-results/prompt-comparison-holdout-1794063740485.json`;
- `data/ai-results/prompt-comparison-recovery-1794064180266.json`;
