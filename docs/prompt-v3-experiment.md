Начало: 2026-11-07; завершение анализа: 2026-11-08. Модель: `stealth/crouton-alpha`, OpenRouter, provider `Stealth`, `temperature=0`. **Решение: v3 оставлен opt-in кандидатом, default не переключён.** Он улучшил фактические основания на известных примерах и превзошёл v1 на сопоставимых новых ответах, но **не превзошёл v2 по совпадению с draft на новом наборе**. Это не выполненный quality gate и не доказанный рост общей accuracy.

## Что добавлено в v3

Файл [`server/prompts/evaluate-v3.txt`](../server/prompts/evaluate-v3.txt), версия `v3`; подключение через `createEvaluator({promptVersion: 'v3'})`. **V1/v2 не редактировались.**

Изменения основаны на [эмпирических проверках гипотез](hypotheses-results.md):

1. Явно трактовать «не оцениваются» как исключение всего перечисления; соблюдать область исключения, не переносить его на независимое явное требование другого критерия.
2. Сначала проверять N/A по контексту, включая сообщения боту. Избыточный вопрос не отменяет достаточность исходных данных; его дефект относится к отдельному применимому критерию процесса.
3. Выбирать ступень по наиболее конкретному подходящему описанию и реальному эпизоду, не смешивать новое обращение, отказ и переспрашивание из-за формулировки.
4. Для утверждений об отсутствии события проверять весь релевантный диапазон, а не одну цитату. Найденный контрпример нельзя игнорировать из-за хорошего позднего ответа.
5. Отделять наблюдаемую полноту от независимо проверенной правильности. Корпоративного справочника нет — его правила не выдумываются.
6. Считать количество результатов из `checklist_version.criteria.length`. Для официальной версии по-прежнему **восемь**, для новой UI-конфигурации — её фактическое число. Все тексты, веса, типы, шкалы и N/A передаются без lookup по c1…c8.

Один вызов на все критерии сохранён. Разбиение, голосование повторов и RAG не внедрялись. V3 не содержит ID диалогов или готовых ответов. Его SHA-256 **`1c60bf7cd77eb4f76fb8ddf90b0944740086bc7ecacc2fbd16896e890af9342e`** закреплён тестом; дальнейшая правка требует новой версии.

## Что принято, а что нет

**Принято в код как доступный кандидат:** отдельная версия v3, динамический N, полная конфигурация, старый JSON-контракт, тесты и возможность осознанного выбора через фабрику/`AI_PROMPT_VERSION`. CLI сравнения получил проверяемую паузу `--delay-ms` (по умолчанию 4000; программная функция сохраняет default 0).

**Не принято как новый default:** v3 не выиграл у v2 на основном сопоставимом новом наборе, сохранил фактические ошибки и изменчивость c2/c7. Улучшения на знакомой регрессии недостаточно. V2 тоже не объявляется готовым default — его прежние блокирующие ограничения не исчезли.

Следующая обоснованная гипотеза — отдельно проверить фазу завершения: первоначальный ответ по существу не должен автоматически засчитываться как итог последующего закрытия. Но очередной длинный промпт или исправление draft под ответ не является проверкой. Для следующей версии нужен отдельный зафиксированный опыт и желательно человеческое согласование спорных N/A/шкал. Новые девять примеров после этого исследования уже нельзя называть независимыми для дальнейшего тюнинга.
