# Проверка официального экспорта и полного DEV

Дата: 2026-11-07. Node.js v26.13.0. Реальная модель `stealth/crouton-alpha`, промпт `v1`, исходная версия чек-листа получена через существующий API с изолированной БД в памяти. Рабочая SQLite не изменялась; маршруты, `score.js` и AI-промпт не менялись.

## Реальная подготовка DEV: PASS

- Полный исходный `invoke.json`: 65 уникальных ID, исходный порядок сохранён.
- Состав: 60 чатов + 5 звонков; 35 RU / 15 KZ / 15 EN.
- Все 65 диалогов получили настоящий валидный ответ: **65 ok / 0 error**, 520 ответов по критериям.
- 81 HTTP-вызов, включая 16 разрешённых repair; синтаксических ошибок JSON — 0.
- Среднее время диалога, включая repair: **18242 мс**, максимум: **29340 мс**.
- Сумма `usage.cost` по всем ответам этого прогона: **$0**.
- На каждом ответе проверены строгий AI-контракт и согласованность с исходной версией. Для всех 65 ответов серверный `calculateScore` даёт конечный итог в диапазоне 0–100.
- Прогон выполнялся CLI с двумя worker; очередь backend не менялась. После первых 25 и затем 50 записей выполнение возобновлялось из журнала, уже готовые ответы не вызывались повторно.

Приватные артефакты:

- `data/ai-results/dev-preparation.json`: результаты модели, snapshot чек-листа, fingerprint входа/реализации/настроек, ID диагностических попыток.
- `data/ai-results/dev-checklist-version.json`: ранее полученная через API полная версия.
- `data/ai-results/dev-preparation-report.json`: машинный отчёт о количестве, времени и стоимости.

Это техническая проверка контракта, не подтверждение точности 520 оценок экспертами. Проблемы качества baseline v1, описанные в [ai-validation.md](ai-validation.md), не устраняются преобразованием формата.

## Экспортёр и CLI: локальная проверка PASS

Команда:

```sh
npm test -- --experimental-test-coverage
```

**510/510 тестов PASS**, без пропусков и падений. Покрытие строк `submission.js` — 100%, ветвей — 99.15%; `prepare-results.js` — 98.37% строк / 91.36% ветвей. Суммарно загруженные тестами файлы — 93.47% строк.

Проверены:

- точные внешние поля JSON 1.0, восемь официальных кодов и типы boolean/число/null;
- запрет пропусков/дублей ID и критериев, неверных шкал и N/A;
- серверный пересчёт, N/A и флаг грубой ошибки без обнуления итога;
- сохранение `checked_range` через полный диапазон `evidence_turns` и пояснение в rationale;
- отдельные безопасные записи ошибок без выдуманных оценок;
- отказ экспорта изменённой рубрики, чтобы не подписывать новый критерий старым внешним кодом;
- resume/max-new, конкуренция 1–3, порядок, lock, запрет затирания повреждённого журнала;
- отказ при изменении данных, версии, модели, промпта или fingerprint;
- prepare-only без команды, export-only без вызовов модели, validate-only;
- санитизация ошибок, редактирование URL в метаданных попыток, приватные файлы 0600.

Независимый read-only обзор существенных ошибок экспорта не выявил. Отдельные build, TypeScript и lint-команды в этом JS-проекте не настроены; вместо них использованы Node syntax check, тесты и диагностика изменённых JS-файлов. В игнорируемом Telegram Python helper редактор показывает отдельные ошибки окружения; он не входит в приложение или эти Node-проверки и в рамках экспорта не изменялся.

Commit/push в рамках подготовки выгрузки не выполнялись. DEV-файл технически готов к публикации; содержательное качество оценок не превращается в экспертный gold от успешной схемы. Следующий шаг — отдельное согласование публикации и подготовка настоящего PROD после выдачи контрольного набора.
